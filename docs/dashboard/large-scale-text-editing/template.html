        02 / Runtime 子视图

        Agent 运行窗口里面发生了什么？

        从发起 client.Agent 到该请求结束，包含 Agent 循环、回放模型等待和工具交互。

        Runtime ≠ 模型累计 + 工具累计

        03 / Runtime 内部观察

        模型：分清累计耗时与平均延迟

        本页是 Strict Replay recorded 时序。数字描述代理请求及 flush；不等于真实上游模型计算、token 数或 Harness 收到的时间。

        单个 HTTP 请求：接收 → 首 SSE flush → 末 SSE flush → handler 结束

        本页 69 个请求的同域边界均完整且有序：三个相邻区间先逐请求计算、再分别累计，可与 HTTP 累计核对。match 已在请求内；首 content / tool delta 与首 SSE 共享接收起点，不能作为额外阶段相加。

        工具：20 次真实 exec，逐条对齐

        单次调用的不同测量边界。按精确 ToolCall ID 与模型轮关联，保留中间失败。

        控制端窗口与 guest 包含同一次执行，不能相加；两者差值也不能称为网络延迟。首输出 / 观察退出是相对时点，不能相加成总耗时。第 4 次 exit 1 三边一致，保留在工作量中。

        后台 job 与 process.wait：两类重叠窗口

        job 从 accepted 到终态；wait 从调用开始到返回。两者可能重叠，wait 也可能在 job 完成后才发起，不能相加。

        独立原生单调时钟域，没有可信 UTC 锚。后台 exec 的 ToolResult 可先返回 accepted；不能把它的 start→result 区间当成整个 guest 执行的父区间。逐 wait→job 映射未导出到此表，不按行号猜边。

        04 / 资源与 Trace

        资源消耗 · CPU 时间不等于墙钟时间

        来自本批三次 L1 运行的同一分析快照。下表为各对象完整采样窗口，可能覆盖准备、执行和评分等待，不能当作仅 Runtime 或单个 Tool 的消耗。1 CPU / 2048 MiB 是 Sandbox 配置。

        内存展示“采样最大值”
        Sandbox 与 Agent 的内存来自定期读数，采样间隙可能漏峰值。控制器 RSS 则是操作系统记录的进程生命周期高水位；三者分别展示。
        保留厂商原始口径
        CPU% 是厂商返回读数，不积分成 CPU 总时间。同一时间戳的冲突值均保留，只展示返回值范围，不生成有效时间序列。华为使用已声明的 MiB 内存字段，时间戳单位仍未核实，不与工具时间轴对齐。I/O 与网络字节当前接口不支持，磁盘占用不作替代。
